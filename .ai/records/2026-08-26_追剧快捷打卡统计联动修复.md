# 2026-08-26 追剧快捷打卡统计联动修复 (Debug / v1.4.1)

## 1. 问题现象与排查
- **现象**：在卡片正面点击 `+1 / -1` 快捷打卡后，卡片正面虽然更新了集数和打卡时间，但统计面板中的影视总时长、月度/年度统计以及趋势图未发生任何变化，数据未联动。
- **根因分析**：
  1. `calculateEpisodeUpdate`（`utils/episodeUtils.ts`）在递增/递减 `currentEpisode` 时，未同步更新 `actualWatchTime`。因此统计计算函数 `calculateTvDuration` 读取旧的 `actualWatchTime` 时，计算得到的单集平均时长被除以新集数，导致总时长完全保持不变（被冻结）。
  2. `components/Stats.tsx` 中的按年/按月过滤只比对了 `movie.addedAt`。对于在历史月份添加但本月打卡的电视剧，在按月统计时被直接过滤排除。
  3. `trendData` 观影趋势图仅按 `movie.addedAt` 累加，未将 `watchHistory` 中的打卡足迹纳入每日/每月趋势。
  4. `App.tsx` 中的列表时间筛选（近 7 天 / 近 30 天 / 按年 / 按月）未比对 `watchHistory` 打卡时间戳。

## 2. 修复方案与核心改动
1. **`utils/episodeUtils.ts`**：
   - 在 `calculateEpisodeUpdate` 的 `delta === 1` 与 `delta === -1` 分支中，根据 `playbackSpeed` 和 `duration` 实时计算新的 `actualWatchTime`：
     `actualWatchTime = Math.round((newEp * duration) / actualSpeed)`。
2. **`components/Stats.tsx`**：
   - 下拉可选年月 (`years`, `months`) 增加 `watchHistory` 遍历，确保有打卡记录的月份均可选择。
   - `filteredMovies` 筛选条件扩展为：`addedAt` 匹配 OR `watchHistory` 中任一打卡记录在所选区间内。
   - `trendData` 趋势图改动为：存在 `watchHistory` 时逐条累加到对应日/月/年。
3. **`App.tsx`**：
   - 列表时间筛选 `dateFilter` 及 `dateOptions` 全面兼容 `watchHistory` 打卡流水。
4. **`tests/quickEpisodeUpdate.test.ts`**：
   - 增加打卡后 `actualWatchTime` 变更与 `calculateTvDuration` / `calculateTotalEpisodes` 动态联动的自动化测试。
